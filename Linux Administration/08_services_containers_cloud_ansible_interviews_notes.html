Module 1: Enterprise Web Servers, NFS Sharing & Docker Containers

Deploying Nginx reverse proxies, network file shares, and containerized microservices.

🇬🇧 English Definition

Administer Nginx/Apache web servers, TLS certificates, and reverse proxies. Share network storage using NFS (Linux) and Samba (SMB/Windows). Package applications with Docker containers sharing the host kernel.

🇮🇳 Hinglish Definition

NFS aur Samba file sharing ke liye use hote hain. Docker application ko dependencies ke saath isolated container me run karta hai.

Core Concepts & Rules

  • Reverse Proxy: Server receiving client requests and forwarding them to backend microservices.
  • Docker vs VM: Containers share host kernel isolating processes; VMs include dedicated guest OS kernel.
  • Docker Commands: docker run -d -p 8080:80 nginx launches background container mapping port 8080.

🔍 Line-by-Line Command Breakdown

  1. Line 1: sudo nginx -t validates Nginx configuration file syntax.
  2. Line 2: mount -t nfs server:/export /mnt/share mounts remote NFS network volume.
  3. Line 3: docker run -d --name web -p 8080:80 nginx starts containerized Nginx instance.

🎯 Interview Focus & Questions

  • Q: What is a reverse proxy?
    A: A server that receives client requests and forwards them to backend services, handling TLS and load balancing.
  • Q: Container vs VM?
    A: A VM includes a full guest OS and kernel; a container shares the host kernel and isolates application processes.

Module 2: Cloud Administration, Ansible Automation & Git

Managing cloud VMs (AWS EC2), versioning scripts with Git, and executing Ansible automation.

🇬🇧 English Definition

Cloud Linux administration combines system administration with cloud security groups, IAM roles, and storage volumes (EBS). Git version-controls scripts and infrastructure code. Ansible automates configuration tasks idempotently.

🇮🇳 Hinglish Definition

Cloud VM ke saath security groups aur IAM samajhna zaroori hai. Ansible se multiple servers ko repeatable automation se manage karte hai.

Core Concepts & Rules

  • Idempotency: An automation task can run repeatedly and converge to the desired target state without unintended changes.
  • Ansible Playbook: YAML declarative document defining target hosts and tasks to execute.

🔍 Line-by-Line Command Breakdown

  1. Line 1: git clone URL downloads repository containing infrastructure scripts.
  2. Line 2: git commit -m 'Update script' records changes to local version history.
  3. Line 3: ansible-playbook -i inventory.ini playbook.yml executes automated server configuration.

🎯 Interview Focus & Questions

  • Q: What is idempotency?
    A: An automation task can run repeatedly and converge to the desired state without unnecessary changes.
💻 Command Example & Terminal Output - Cloud Administration, Ansible Automation & Git

git add .

Module 3: Troubleshooting Scenarios & L1/L2/L3 Interview Preparation

Structured troubleshooting methodology, scenario question strategies, and interview response frameworks.

🇬🇧 English Definition

Structure troubleshooting responses using the Golden Interview Framework: Impact -> Evidence -> Isolation -> Safe Remediation -> Validation -> Root Cause Prevention.

🇮🇳 Hinglish Definition

Interview me answer structure: Pehle impact batao, phir evidence, failing layer isolate karo, safe fix do, validate karo aur root cause prevention explain karo.

Core Concepts & Rules

  • L1 Focus: Standard administration commands, file permissions, user accounts, and service restarts.
  • L2 Focus: Storage extension (LVM), DNS resolution, SSH hardening, network troubleshooting, and script automation.
  • L3 Focus: Infrastructure architecture, container orchestration, cloud security, performance profiling, and incident RCA.

🔍 Line-by-Line Command Breakdown

  1. Step 1: Confirm Impact: Identify affected applications, users, and server scope.
  2. Step 2: Collect Evidence: Inspect status (systemctl status), logs (journalctl -u), and metrics (top/df).
  3. Step 3: Isolate Layer: Narrow down to interface, route, DNS, firewall, service, or permission layer.
  4. Step 4: Safe Fix & Validation: Apply minimum change, verify resolution, and document prevention.

🎯 Interview Focus & Questions

  • Q: Best interview troubleshooting pattern?
    A: Explain Impact -> Evidence -> Isolation -> Safe Remediation -> Validation -> Root Cause Prevention.
