2. Relational Table Structure (ER Diagram)

Hum is master guide mein 4 Relational Tables banayenge: departments, employees, projects, aur employee_projects (Bridge Table).

departments | | department_id (Primary Key -> Foreign Key) | employees | | employee_id (Primary Key -> Foreign Key) | employee_projects (Bridge / Junction Table) | | project_id (Foreign Key <- Primary Key) | projects
  • departments: Department details store karega (Primary Key: department_id).
  • employees: Employee details & department link store karega (Primary Key: employee_id, Foreign Key: department_id).
  • projects: Project info & budgets store karega (Primary Key: project_id).
  • employee_projects: Many-to-Many relationship bridge table (Composite Primary Key: employee_id, project_id).

3. Table Creation & Constraints Explanation

A. Departments Table

</> SQL 
CREATE TABLE departments (
    department_id INT PRIMARY KEY AUTO_INCREMENT,
    department_name VARCHAR(50) NOT NULL,
    location VARCHAR(50)
);

B. Employees Table (with Foreign Key)

</> SQL 
CREATE TABLE employees (
    employee_id INT PRIMARY KEY AUTO_INCREMENT,
    employee_name VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE,
    salary DECIMAL(10,2),
    department_id INT,
    manager_id INT,
    
    FOREIGN KEY (department_id)
    REFERENCES departments(department_id)
);

C. Projects Table

</> SQL 
CREATE TABLE projects (
    project_id INT PRIMARY KEY AUTO_INCREMENT,
    project_name VARCHAR(100) NOT NULL,
    project_budget DECIMAL(12,2)
);

D. Employee Projects Table (Bridge Table with Composite Primary Key)

</> SQL 
CREATE TABLE employee_projects (
    employee_id INT,
    project_id INT,
    
    PRIMARY KEY (employee_id, project_id),
    
    FOREIGN KEY (employee_id)
    REFERENCES employees(employee_id),
    
    FOREIGN KEY (project_id)
    REFERENCES projects(project_id)
);

5. INNER JOIN Deep Dive

Simple Definition

INNER JOIN sirf woh records return karta hai jinka dono tables (Table 1 aur Table 2) mein matching record available ho based on the ON condition.

Why Neha is Omitted?

Neha ka department_id NULL hai, isliye employees.department_id = departments.department_id match nahi hota, aur Neha result mein nahi aati.

</> SQL 
SELECT
    employees.employee_name,
    departments.department_name
FROM employees
INNER JOIN departments
ON employees.department_id = departments.department_id;
Query Result Output

6. LEFT JOIN Deep Dive

Simple Definition

LEFT JOIN (ya LEFT OUTER JOIN) Left Table ke saare records return karta hai, chahe Right Table mein matching record ho ya na ho. Agar right table mein match na ho, toh NULL values aati hain.

Why Neha Appears Here?

Left table employees mein Neha hai. Right table departments mein match na hone ki wajah se department_name column mein NULL display hoga.

</> SQL 
SELECT
    employees.employee_name,
    departments.department_name
FROM employees
LEFT JOIN departments
ON employees.department_id = departments.department_id;

7. RIGHT JOIN Deep Dive

Simple Definition

RIGHT JOIN (ya RIGHT OUTER JOIN) Right Table ke saare records return karta hai, chahe Left Table mein matching record ho ya nahi.

8. FULL OUTER JOIN (using UNION in MySQL)

Simple Definition

FULL OUTER JOIN dono tables ke saare records ko combine karke dikhata hai. Jinka match hota hai woh match hote hain, baaki jagah NULL show hota hai.

MySQL Solution (LEFT JOIN + RIGHT JOIN + UNION)

MySQL mein direct FULL OUTER JOIN syntax supported nahi hota. Isliye hum LEFT JOIN aur RIGHT JOIN queries ko UNION se combine karte hain.

</> SQL 
SELECT
    employees.employee_name,
    departments.department_name
FROM employees
LEFT JOIN departments
ON employees.department_id = departments.department_id

UNION

SELECT
    employees.employee_name,
    departments.department_name
FROM employees
RIGHT JOIN departments
ON employees.department_id = departments.department_id;

9. CROSS JOIN (Cartesian Product)

CROSS JOIN pehli table ke har single record ko doosri table ke har single record ke sath combine karta hai (Cartesian Product).

Row Calculation Formula

Agar Table 1 mein 6 records hain aur Table 2 mein 5 records hain, toh CROSS JOIN total 6 × 5 = 30 rows return karega.

No ON Condition Needed

CROSS JOIN mein koi ON condition nahi di jaati kyunki yeh matching par nahi balki har possible combination par kaam karta hai.

</> SQL 
SELECT
    employees.employee_name,
    departments.department_name
FROM employees
CROSS JOIN departments;

10. SELF JOIN (Manager-Employee Relationship)

Simple Definition

Jab hum same table ko khud ke saath JOIN karte hain, use SELF JOIN kehte hain. Yeh hierarchical data (jaise Employee and Manager) ke liye exact requirement hoti hai.

Table Aliases (e and m)

Table aliases e (for Employee view) aur m (for Manager view) ka use karke hum same table ko do alag roles mein treat karte hain: e.manager_id = m.employee_id.

</> SQL 
SELECT
    e.employee_name AS Employee,
    m.employee_name AS Manager
FROM employees e
LEFT JOIN employees m
ON e.manager_id = m.employee_id;

12. JOIN + WHERE, ORDER BY & GROUP BY Clauses

A. JOIN + WHERE (Filtering IT Department Only)

</> SQL 
SELECT
    e.employee_name,
    d.department_name
FROM employees e
INNER JOIN departments d
ON e.department_id = d.department_id
WHERE d.department_name = 'IT';

B. JOIN + ORDER BY (Sorting Salaries Descending)

</> SQL 
SELECT
    e.employee_name,
    d.department_name,
    e.salary
FROM employees e
INNER JOIN departments d
ON e.department_id = d.department_id
ORDER BY e.salary DESC;

C. JOIN + GROUP BY (Department Average Salary)

</> SQL 
SELECT
    d.department_name,
    AVG(e.salary) AS average_salary
FROM departments d
LEFT JOIN employees e
ON d.department_id = e.department_id
GROUP BY d.department_id, d.department_name;

13. JOIN + HAVING (Group-Level Filters)

WHERE vs HAVING Difference

WHERE: Individual rows ko filter karta hai pehle (before grouping).

HAVING: Aggregated groups ko filter karta hai (after GROUP BY execution).

Query Goal

Sirf woh departments list karo jinme 1 se zyada employees (total_employees > 1) kaam karte hain.

</> SQL 
SELECT
    d.department_name,
    COUNT(e.employee_id) AS total_employees
FROM departments d
LEFT JOIN employees e
ON d.department_id = e.department_id
GROUP BY d.department_id, d.department_name
HAVING COUNT(e.employee_id) > 1;
Query Result Output
department_nametotal_employees
IT2

15. Primary Key, Foreign Key & Relational Constraints

  • PRIMARY KEY: Uniquely identifies each record in a table. Cannot be NULL or duplicate (e.g. department_id INT PRIMARY KEY).
  • FOREIGN KEY: Establishes a link/relationship between two tables by pointing to Primary Key of parent table (e.g. FOREIGN KEY (department_id) REFERENCES departments(department_id)).
  • COMPOSITE PRIMARY KEY: A primary key made of multiple columns combined together (e.g. PRIMARY KEY (employee_id, project_id) in bridge table).
  • UNIQUE: Prevents duplicate values in a column (e.g. email VARCHAR(100) UNIQUE).
  • NOT NULL: Prevents column from holding empty/NULL values (e.g. department_name VARCHAR(50) NOT NULL).
  • AUTO_INCREMENT: Automatically generates sequential integer numbers (1, 2, 3...) when new records are inserted.

CREATE DATABASE office;

CREATE TABLE departments (
    department_id INT PRIMARY KEY AUTO_INCREMENT,
    department_name VARCHAR(50) NOT NULL,

    employee_id INT PRIMARY KEY AUTO_INCREMENT,

    email VARCHAR(100) UNIQUE,

CREATE TABLE projects (
    project_id INT PRIMARY KEY AUTO_INCREMENT,

CREATE TABLE employee_projects (
    employee_id INT,

    FOREIGN KEY (employee_id)
    REFERENCES employees(employee_id),

    FOREIGN KEY (project_id)
    REFERENCES projects(project_id)
);
