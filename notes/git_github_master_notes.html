Module 1. Version Control & Setup

1.1 What is Version Control System (VCS)?

A Version Control System (VCS) is software that tracks and records changes made to files over time so that you can recall specific versions later, compare revisions, restore lost code, and collaborate smoothly with a team.

Centralized VCS (CVCS)

Examples: Subversion (SVN), Perforce.
A single central server contains all versioned files. If the central server goes down, developers cannot collaborate or save version history.

Distributed VCS (DVCS)

Examples: Git, Mercurial.
Every developer fully mirrors (clones) the entire repository, including full commit history, locally on their machine. Work continues even offline!

1.3 First Time Git Configuration

After installing Git, configure your global user identity so every commit is tagged with your name and email.

</> GIT COMMANDS 
-- Set global user name
git config --global user.name "Gagan Sir"

-- Set global user email
git config --global user.email "gagan@example.com"

-- Set default main branch name
git config --global init.defaultBranch main

-- Verify configurations
git config --list

Module 2. Git 3-Stage Architecture

Git manages project files across Three Main Areas (Working Tree, Staging Area, Local Repository):

1. Working Directory

The local folder where you actively create, edit, or delete code files. Files here are either Untracked or Modified.

2. Staging Area (Index)

A middle-ground buffer file (index) holding changes you select to be included in the next commit preview.

3. Local Repository (.git)

The permanent database inside the hidden .git folder storing snapshot commits and history pointers.

File Lifecycle in Git

Workflow Flowchart

Untracked / Modified File → git add → Staged Area → git commit → Committed (Local Repo)

Module 3. Essential Git Commands (Daily Workflow)

3.1 Initializing & Checking Repository

</> GIT COMMANDS 
-- Initialize a new empty Git repository
git init

-- Check the current status of files
git status

3.2 Staging & Committing Changes

</> GIT COMMANDS 
-- Stage a specific file
git add index.html

-- Stage all modified and new files
git add .

-- Commit staged files with descriptive message
git commit -m "Add user authentication module"

-- Shortcut: Stage modified tracked files and commit in one go
git commit -am "Fix login validation bug"

3.3 Viewing History & Differences

</> GIT COMMANDS 
-- View commit history
git log

-- Compact single-line history with graph
git log --oneline --graph --all

-- See unstaged changes in working directory
git diff

-- See staged changes waiting to be committed
git diff --staged

Module 4. Undoing Changes & Resetting

4.1 .gitignore File

Create a .gitignore file at your project root to prevent temporary files, API secrets, or large dependencies from being tracked by Git.

</> .gitignore 
-- Ignore node_modules folder
node_modules/

-- Ignore environment secrets
.env

-- Ignore all .log files
*.log

-- Ignore OS files
.DS_Store
Thumbs.db

4.2 Undoing Work & Resetting Modes

CommandTarget AreaBehavior / Result
git restore file.txtWorking DirectoryDiscards local uncommitted modifications in working copy.
git restore --staged file.txtStaging AreaUnstages file back to working directory.
git commit --amend -m "msg"Latest CommitModifies the last commit message or includes newly staged files.
git reset --soft HEAD~1Local RepoUndoes commit, keeps changes staged in index.
git reset --mixed HEAD~1Local Repo & IndexDefault: Undoes commit & un-stages changes to working dir.
git reset --hard HEAD~1All AreasDESTRUCTIVE: Wipes out commit, staged files, and working changes!
git revert <commit-hash>Local RepoSafe public undo: creates a NEW commit that reverses previous commit.

Module 5. Git Branching & Merging Masterclass

Branching allows developers to diverge from the main line of development to isolate feature work or bug fixes.

5.1 Branching Commands

</> GIT COMMANDS 
-- List all local branches
git branch

-- Create a new branch
git branch feature-payment

-- Switch to branch (Modern syntax)
git switch feature-payment

-- Create and switch in one command
git switch -c feature-dashboard

-- Delete merged branch
git branch -d feature-payment

-- Force delete unmerged branch
git branch -D feature-payment

5.2 Merging Strategies & Resolving Conflicts

Fast-Forward Merge

Occurs when the target branch has no intermediate commits. Git simply moves the branch pointer forward.

3-Way Merge Commit

Occurs when branches have diverged. Git creates a new merge commit combining two distinct histories.

Resolving Merge Conflicts Step-by-Step

When Git cannot automatically resolve differences, it inserts conflict markers:

<<<<<<< HEAD
Code on current branch
=======
Code on incoming branch
>>>>>>> feature-branch

1. Open file and edit code to final desired state.
2. Run git add resolved_file.py
3. Run git commit -m "Resolve merge conflict"

Module 6. Stashing, Reflog & Advanced Tools

6.1 Git Stash (Temporarily Saving Work)

Use stashing when you need to switch branches quickly without committing incomplete work.

</> GIT COMMANDS 
-- Save modified tracked files into stash stack
git stash

-- Save with custom message including untracked files
git stash save "WIP: navbar styling" -u

-- View list of stashed items
git stash list

-- Re-apply most recent stash and remove it from list
git stash pop

-- Clear all stashes
git stash clear

6.2 Emergency Recovery with Reflog

git reflog records every single move of HEAD in your repository. If you accidentally delete a branch or hard-reset a commit, reflog lets you restore it!

</> GIT COMMANDS 
-- View full movement history of HEAD
git reflog

-- Restore lost commit using HEAD@{index}
git reset --hard HEAD@{3}

Module 7. Remote Repositories & GitHub

</> GIT COMMANDS 
-- Connect local repo to remote GitHub URL
git remote add origin https://github.com/username/project.git

-- Check remote URLs
git remote -v

-- Push code and set upstream tracking
git push -u origin main

-- Fetch remote changes without merging
git fetch origin

-- Fetch and merge remote changes in one command
git pull origin main

git fetch vs git pull

git fetch downloads latest remote commits to remote-tracking branches (origin/main) without modifying your local code.
git pull is equivalent to git fetch + git merge.

Module 8. GitHub Collaboration & Pull Requests

Standard Pull Request (PR) Workflow

  1. Fork / Clone repository.
  2. Create feature branch: git switch -c feature-new-api.
  3. Make modifications, stage, and commit: git commit -m "Add API endpoints".
  4. Push feature branch to remote: git push -u origin feature-new-api.
  5. Open Pull Request (PR) on GitHub for team code review.
  6. After approval, merge PR into main branch.

Module 9. Rebasing & Professional Workflows

9.1 Git Rebase vs Git Merge

Git Merge

Preserves complete chronological history by adding a 3-way merge commit. Non-destructive.

Git Rebase

Re-applies your commits on top of another base tip to maintain a clean linear commit history.

</> GIT COMMANDS 
-- Rebase current feature branch onto main
git rebase main

-- Interactive rebase to squash last 3 commits
git rebase -i HEAD~3

Golden Rule of Rebasing

NEVER rebase commits that have been pushed to a public shared branch! Only rebase private local feature branches before merging.
