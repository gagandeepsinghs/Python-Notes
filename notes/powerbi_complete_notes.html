Module 1: Introduction to Power BI & Ecosystem Architecture

What is Power BI?

Power BI is a Microsoft business analytics service that connects to hundreds of data sources, transforms messy data into structured models, performs high-speed dynamic calculations via DAX, and renders interactive reports and dashboards.

The Power BI Ecosystem Components

  • Power BI Desktop: Free Windows application for authoring ETL, data modeling, DAX measures, and reports.
  • Power BI Service: Cloud SaaS platform (app.powerbi.com) for publishing, sharing dashboards, and scheduling refreshes.
  • Power BI Mobile: Native iOS/Android app to view live dashboards.
  • Power BI Gateway: Secure bridge connecting cloud service to on-premises databases.

The End-to-End Business Intelligence Workflow

  1. Extract & Transform (Power Query): Connect to raw sources, clean data, and shape tables.
  2. Model Data (Data View & Model View): Create relationships between tables using Star Schema principles.
  3. Calculate Metrics (DAX): Write Data Analysis Expressions for KPIs, Time Intelligence, and dynamic totals.
  4. Visualize Data (Report View): Drag and drop visuals, visuals formatting, slicers, and bookmarks.
  5. Publish & Share (Power BI Service): Push report to cloud workspace, create dashboards, set up RLS, and schedule data refresh.

Module 3: Data Ingestion, Storage Modes & Power Query ETL

Power BI Data Storage Modes

1. Import Mode: Loads complete dataset into memory. Uses VertiPaq columnar compression. Ultra-fast DAX performance.

2. DirectQuery: Queries source database in real-time. Zero storage memory in Power BI, but depends on database speed.

3. Dual / Composite: Combines Import and DirectQuery modes across different tables in one model.

Essential Power Query Transformations

  • Unpivot Columns: Transforms wide cross-tab format (Jan, Feb, Mar as columns) into attribute-value rows.
  • Merge Queries: Joins two tables side-by-side using key matching (SQL Join).
  • Append Queries: Stacks two tables vertically (SQL UNION).
Power Query M Language Sample - Custom Applied Step
// Unpivoting Monthly Sales Columns in M Code
= Table.UnpivotOtherColumns(PreviousStep_ChangedType, {"ProductID", "Category"}, "Month", "SalesAmount")

Module 4: Data Modeling & Star Schema Architecture

Data modeling is the foundation of Power BI. A bad data model makes DAX complex and slow. A clean Star Schema makes DAX simple and ultra-fast.

Table Type Characteristics Contents & Columns
Fact Table (Sales, Orders, Transactions) Central table in Star Schema. Contains transactional events recorded over time. High row count. Foreign Keys (CustomerID, ProductID, DateKey) and Numeric Metrics (SalesAmount, Quantity, Discount).
Dimension Table (Customer, Product, Date, Location) Surrounds the Fact Table. Provides descriptive context for filtering and grouping metrics. Low row count. Primary Keys (CustomerID) and Text Attributes (Customer Name, Category, Segment, Country, City).

Relationship Cardinalities & Filter Directions

  • One-to-Many (1:*): Best practice. 1 on Dimension side (unique keys), * on Fact side (repeated keys).
  • Single Filter Direction: Filter flows from 1 side (Dimension) to * side (Fact). Avoid Bi-directional filtering unless strictly required.
  • Active vs Inactive Relationships: Only one relationship between two tables can be active at a time. Inactive relationships are activated using USERELATIONSHIP() in DAX.

Module 5: Introduction to DAX, Calculated Columns vs Measures

Calculated Columns

Evaluated line-by-line during data refresh. Stored permanently in RAM memory. Has automatic Row Context.

Use when: Creating a slicer attribute or row grouping.

Measures (DAX Best Practice)

Evaluated dynamically on the fly based on report slicer/filter selections. Takes zero RAM storage space.

Use when: Aggregating numbers, KPIs, totals, % calculations.

Filter Context vs Row Context

Row Context: The current active row being evaluated (available in Calculated Columns and X-functions like SUMX).

Filter Context: The environment of filters applied to a visual by slicers, report filters, rows, and columns.

DAX Formula Syntax - Calculated Column vs Measure
-- Calculated Column (Evaluates Row by Row)
Margin_Column = Sales[Revenue] - Sales[Cost]

-- Measure (Evaluates Dynamically in Filter Context)
Total_Sales = SUM(Sales[Revenue])

Module 6: Scalar Aggregations & Iterative X-Functions

DAX Function Category Behavior & Expression Syntax
SUM(Column) Scalar Aggregation Sums all values in a single numeric column within filter context.
SUMX(Table, Expression) Iterative X-Function Iterates row-by-row over Table, evaluates Expression per row, and sums final totals.
AVERAGEX(Table, Expression) Iterative X-Function Iterates row-by-row and calculates average of the expression results.
DIVIDE(Num, Denom, [Alt]) Safe Division Performs safe division. Returns Alt (or Blank) if denominator is zero (prevents DIV/0 Error).
DAX Code Examples - Iterative Calculations & Safe Division
-- Calculate Revenue without creating a calculated column
Total Revenue = SUMX(Sales, Sales[Quantity] * Sales[UnitPrice])

-- Calculate Profit Margin % safely
Profit Margin % = 
DIVIDE(
    [Total Profit],
    [Total Revenue],
    0
)

Module 7: The Master CALCULATE Function & Filter Modifiers

CALCULATE is the single most important function in DAX. It evaluates an expression while modifying or overwriting the existing Filter Context.

DAX Syntax - CALCULATE Master Formula
CALCULATE( Expression, Filter1, Filter2, ... )
Filter Modifier DAX Syntax Behavior & Purpose
ALL ALL(TableOrColumn) Removes all filters from specified table/column. Used for % of Total calculations.
ALLEXCEPT ALLEXCEPT(Table, Col1) Removes all filters from Table except specified column(s).
ALLSELECTED ALLSELECTED() Removes visual grid filters while respecting explicit slicer filters.
USERELATIONSHIP USERELATIONSHIP(Col1, Col2) Activates an inactive relationship for the duration of the measure.
DAX Measures - Using CALCULATE, ALL, and Inactive Relationships
-- Total Sales for East Region Only
East Sales = CALCULATE([Total Sales], Customer[Region] = "East")

-- Percentage of Total Sales (% of All Categories)
% of Total Sales = 
DIVIDE(
    [Total Sales],
    CALCULATE([Total Sales], ALL(Product[Category]))
)

-- Sales by Ship Date (Using Inactive Relationship)
Sales by Ship Date = 
CALCULATE(
    [Total Sales],
    USERELATIONSHIP(Sales[ShipDateKey], 'Date'[DateKey])
)

Module 8: Time Intelligence DAX Functions (YTD, YoY Growth)

The Date Table Mandate

For Time Intelligence DAX to work correctly, you MUST have a dedicated Date Dimension Table marked as a Date Table with contiguous, non-duplicate dates.

Creating a DAX Date Table

Date = CALENDAR(DATE(2020,1,1), DATE(2030,12,31))

Metric Type DAX Function Example Formula Code
Year-to-Date (YTD) TOTALYTD / DATESYTD Sales YTD = TOTALYTD([Total Sales], 'Date'[Date])
Prior Year Sales SAMEPERIODLASTYEAR Sales PY = CALCULATE([Total Sales], SAMEPERIODLASTYEAR('Date'[Date]))
Period Shift DATEADD Sales M M = CALCULATE([Total Sales], DATEADD('Date'[Date], -1, MONTH))
DAX Measures - Year-over-Year (YoY) Growth % Pattern
-- 1. Sales Prior Year
Sales PY = 
CALCULATE(
    [Total Sales],
    SAMEPERIODLASTYEAR('Date'[Date])
)

-- 2. YoY Sales Variance
YoY Sales Growth = [Total Sales] - [Sales PY]

-- 3. YoY Growth Percentage %
YoY Sales Growth % = 
DIVIDE(
    [YoY Sales Growth],
    [Sales PY],
    0
)

Module 9: Advanced DAX Patterns, VAR Variables & Row-Level Security (RLS)

DAX Code - Using VAR Variables & RANKX
-- Top Performing Products Ranking using VAR Variables
Product Rank = 
VAR CurrentSales = [Total Sales]
VAR IsProductInContext = HASONEVALUE(Product[ProductName])
RETURN
IF(
    IsProductInContext,
    RANKX(
        ALL(Product[ProductName]),
        [Total Sales],
        CurrentSales,
        DESC
    ),
    BLANK()
)

Dynamic Row-Level Security (RLS) Setup

Row-Level Security restricts data access for given users. In Power BI Desktop: Modeling Tab → Manage Roles → Add DAX Filter.

DAX RLS Filter Syntax
-- Dynamic RLS DAX Filter on User Email
UserSecurityTable[Email] = USERPRINCIPALNAME()

Module 10: Data Visualization & Interactive Report Features

Module 12: Performance Tuning & DAX Optimization

Optimization Focus Best Practice Recommendation
DAX Measures vs Columns Avoid Calculated Columns where possible. Use Measures to preserve VertiPaq RAM memory.
Safe Division Always use DIVIDE(a, b) instead of a / b operator.
DAX Variables Use VAR ... RETURN syntax to prevent re-evaluating identical sub-expressions.
High Cardinality Remove high-cardinality columns (like timestamps or unique GUID strings) if not needed for reporting.
Performance Analyzer Use Power BI's Performance Analyzer to inspect visual query execution durations.
