Shard Key Strategy
🇬🇧 English Definition
A shard key determines how data is distributed across cluster shards. Targeted queries including the shard key avoid scatter-gather broadcasts across all nodes.
🇮🇳 Hinglish Definition
Shard key choose karte waqt high cardinality aur query targeting ka dhyan rakhna chahiye taaki data evenly distribute ho.

Scenario-Based Interview Questions
💡 Real-World Troubleshooting Scenarios
  • Slow Query: Use `explain()` → check index usage → compare examined vs returned docs → review schema & projection.
  • Duplicate Records: Verify unique business rules → clean duplicates → create unique index.
  • High Memory Usage: Inspect working set size → evaluate index count → optimize query patterns.
  • Primary Node Failure: Inspect replica set status & election logs → verify driver failover retry logic.
  • Horizontal Scale Requirement: Measure performance → optimize indexes → evaluate sharding architecture.

Interview Question Bank (35 Questions)
❓ Core Concept Interview Q&A
  • Q: What is BSON? Binary JSON storing typed key-value pairs (e.g., Date, ObjectId, Int64).
  • Q: `insertOne` vs `insertMany`? `insertOne` writes single doc; `insertMany` writes array batch with optional `{ordered: false}`.
  • Q: Difference between `updateOne` and `replaceOne`? `updateOne` modifies specific fields via `$set`/`$inc`, while `replaceOne` overwrites entire matching document.
  • Q: What is an index scan vs collection scan? IXSCAN uses index B-tree; COLLSCAN scans every document sequentially (slow).
  • Q: How does `$lookup` work? Performs left outer join between local collection field and foreign collection field.
  • Q: What are Change Streams? Real-time notification mechanism listening to collection changes via `watch()`.
