Git and GitHub Fundamentals & Mental Model
🇬🇧 English Definition
Git is a distributed version-control system that tracks local file changes, commits, and branch history. GitHub is a cloud hosting platform for Git repositories that adds collaboration tools like Pull Requests, Code Review, Issues, Actions CI/CD, and Security scanning.
🇮🇳 Hinglish Definition
Git tumhare local machine par code changes aur history ko track karta hai. GitHub isi code ko online host karke team collaboration, review aur automation provide karta hai.

Git File Lifecycle
🇬🇧 English Definition
Git moves changes through 4 main states: Untracked/Modified, Staged (index buffer), Committed (local repository snapshot), and Pushed (GitHub remote repository).

File pehle working tree mein change hoti hai, phir `git add` se staging area mein jaati hai, `commit` se local history mein aur `push` se GitHub par.

    Merge and Fast-Forward
    git switch main git pull --ff-only git merge feature/user-login // Abort conflicted merge git merge --abort
    🇬🇧 Fast-Forward Merge
    Fast-forward occurs when the target branch HEAD has no divergent commits; Git moves the main pointer forward directly without creating an explicit merge commit.
    🇮🇳 Non-Fast-Forward Merge
    Jab dono branches par alag-alag commits ban jaate hain, toh Git divergent histories ko merge commit ke through combine karta hai.

    Merge Conflicts Resolution
    git status git diff // Resolution Steps: // 1. Manually edit file to remove conflict markers and select clean code // 2. Stage resolved file: git add app.py git commit -m "fix: resolve merge conflict in app.py" // Cancel merge if needed: git merge --abort

    Rebase and Interactive Rebase
    git fetch origin git switch feature/login git rebase origin/main // Interactive Rebase (Clean last 5 commits) git rebase -i HEAD~5
    ActionMeaning
    pickKeep commit in history as is
    rewordKeep commit but edit commit message
    editPause rebase to modify commit content
    squashCombine commit into previous commit
    fixupCombine commit into previous commit and discard message
    dropRemove commit completely from history
    🎯 Golden Rule of Rebase
    Never rebase commits that have already been pushed to a shared/protected public branch. Use rebase strictly for cleaning up private local feature branches before merging.

    Restore vs Reset vs Revert
    GoalCommandBest Use Case & Safety
    Discard file changesgit restore fileUnstaged local changes
    Unstage filegit restore --staged fileRemove file from staging index
    Undo shared commitgit revert SHASafe for team/remote history
    Move HEAD, keep changesgit reset --soft HEAD~1Local history cleanup
    Move HEAD and indexgit reset HEAD~1Local history cleanup
    Discard local changesgit reset --hard HEAD~1Dangerous; rewrites history permanently
    git restore app.py git restore --staged app.py git revert abc1234 git reset --soft HEAD~1 git reset HEAD~1 git reset --hard HEAD~1

    Reflog and Recovery
    🇬🇧 English Definition
    Git reflog (reference log) records every movement of HEAD and local branch pointers. It allows recovering lost commits, deleted branches, or aborted rebases.
    🇮🇳 Hinglish Definition
    Reflog Git ke sabhi local pointer movements ka record rakhta hai. Galti se reset ya branch delete hone par reflog se exact SHA dhoondh kar recover kar sakte hain.
    git reflog git reflog show main // Recover lost commit by creating a new branch at lost SHA git switch -c recovery_branch abc1234 git show abc1234

    GitHub Actions is an automated workflow engine integrated into GitHub. Workflows are declared in YAML under `.github/workflows/`. Workflows respond to events, execute jobs on runners, and run sequential steps.

    150+ Interview Questions & Scenario-Based Answers
    🎯 Key Scenario Answers
    Scenario: Bad commit merged to main? Do not rewrite shared history. Assess impact, revert the bad commit (`git revert SHA`), run CI checks, communicate with team, then fix forward.

    Scenario: Secret committed? Rotate and revoke credentials immediately! Investigate exposure, remove secret from current code, remediate Git history if required, and enable secret scanning push protection.
